# Наряд №006 — Кадры: детекция сцен, прореживание, дедупликация, оценка резкости

**Волна:** 1 (Индексатор)  
**Стадия:** indexer  
**Размер:** M  
**Исполнитель:** agent  
**Зависит от:** #34, #35, #5  
**Связанные ADR:** —  
**Статус:** open

## Контекст
Из видео нужно получить набор кадров-кандидатов: ключевые кадры сцен плюс равномерная выборка, без дублей и размытых кадров. Это CPU-стадия без внешних API.

## Контракт
```
runs/<id>/normalized.mp4
→ frames/*.jpg + frames.json: t, scene_id, sharpness (дисперсия Лапласиана), phash, exposure (средняя яркость, доля пересвета)
```
Параметры в конфигурации: порог детектора сцен, шаг выборки (по умолчанию 1 кадр в 2–3 с), порог дубликатов (расстояние pHash), порог резкости.

## Scope
- PySceneDetect для границ сцен; ключевой кадр из середины каждой сцены; плюс равномерная выборка.
- Дедупликация по pHash (внутри сцены и между соседними сценами), пометка отбракованных вместо удаления (в `frames.json` поле `rejected` с причиной).
- Оценки: резкость, экспозиция (пересвет и недосвет).
- Детерминированный результат на одном и том же видео.

## Non-goals
- Эстетическая оценка и семантика кадров (стадия отбора).
- Любые вызовы внешних API.

## Acceptance criteria
- [ ] На `scenes.mp4` обнаружены все 4 известные склейки с допуском ±0.5 с
- [ ] Почти дублирующий фрагмент свёрнут в один кадр, размытый фрагмент имеет резкость ниже порога и помечен
- [ ] Число кадров на 30-секундном ролике укладывается в ожидаемые границы (в тесте)
- [ ] `frames.json` валиден по схеме из №35
- [ ] Повторный запуск даёт идентичный `frames.json`
- [ ] CI зелёный

## Assumptions / Open questions
- Пороги по умолчанию подбираются на фикстурах и корректируются после эталонного набора (шлюз B).

## Проверка аудитора
- Проверить, что отбракованные кадры не теряются бесследно (причина записана).
- Проверить на видео с длинной статичной сценой и на видео с частыми склейками (дополнительный синтетический случай).
