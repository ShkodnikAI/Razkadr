# Движок раскладки (layout, наряд №021)

Движок превращает Storyboard в формат-нейтральные слайды `slides.json`
(схема `schemas/slides.v1.json`): слоты, ссылки на эпизоды и предупреждения.
Рендеры (PPTX №022, HTML №026, PDF №024) строятся из этого документа и не
знают про Storyboard (ADR-0003: раскладка отделена от формата вывода).
Работает и на Storyboard без текста (волна 2), и с текстом (волна 3).

```bash
razkadr layout storyboard.json [--lang ru|en] [--out slides.json] [--config razkadr.toml]
```

Выход по умолчанию — `slides.json` рядом со Storyboard; коды выхода:
0 — ок, 1 — Storyboard не валиден, 2 — файл/ошибка конфигурации. Два запуска
на одних входных данных дают байт-идентичный файл (детерминизм — тест).

## Макеты и слоты

| Макет | Слоты | Откуда |
|---|---|---|
| `title` | `heading` (заголовок проекта), `subheading` (текст hero), `frame` (кадр hero фоном) | строится всегда, из `project` + первого hero-эпизода |
| `hero_caption` | `frame`, `caption` (текст эпизода), `timecode` | каждый hero-эпизод |
| `ingredients_list` | `frame` (первый эпизод группы), `heading` («Ингредиенты»), `items` (строки списка) | группа эпизодов роли |
| `steps_grid` | `columns` (2 или 3), `heading` («Шаги»), `cells` | группа эпизодов роли; ячейка: `frame`, `number`, `text`, `timecode` |
| `serving` | `frame`, `caption`, `timecode`, `heading` («Подача») | каждый serving-эпизод |

Слот кадра: `{path, t, episode_id}` — путь и время из Storyboard без
изменений. `source_refs` — id эпизодов, питающих слайд (у `title` это
`["project"]`, слайды-продолжения повторяют id эпизода). Таймкод — строка
`мм:сс` (или `ч:мм:сс` от часа) от `t_start` эпизода, с округлением вниз.

## Выбор макета для роли

Отображение роли → макет живёт в конфигурации, в коде не зашито:

```toml
[layout.role_layouts]
hero = "hero_caption"
ingredients = "ingredients_list"
prep = "steps_grid"
steps = "steps_grid"
serving = "serving"
```

Значения по умолчанию (таблица-семя, переопределяется конфигом): перечисленные
пять ролей пресета `recipe` плюс `step` (единственное число — так названа роль
в канонических примерах `examples/storyboard.*.json`). Роль без отображения не
падает: её эпизоды пропускаются, в документ пишется предупреждение
`unmapped_role` с числом пропущенных эпизодов. Неизвестный макет в конфиге —
явная ошибка `LayoutError` (код выхода 2).

## Лимиты и автоподгон текста

Лимиты настраиваются в `[layout]` (значения по умолчанию уточняются
эталонным шаблоном, №022):

| Параметр | По умолчанию | Слот |
|---|---|---|
| `heading_max` | 60 | заголовок `title` |
| `subheading_max` | 120 | подзаголовок `title` |
| `caption_max` | 180 | подписи `hero_caption`/`serving` |
| `item_max` | 40 | строка `ingredients_list` |
| `step_text_max` | 120 | текст ячейки `steps_grid` |
| `ingredients_max_items` | 12 | строк на один слайд списка |
| `steps_max_cells` | 6 | ячеек на один слайд сетки |

Порядок автоподгона: сначала перенос на новый слайд (список — по 12 строк,
сетка — по 6 ячеек; ровно N элементов умещается на один слайд, N+1 — уже два),
затем сокращение по границе предложения (если предложение покрывает не менее
половины лимита), иначе по границе слова, с многоточием «…». Каждое
сокращение пишется в `warnings` того слайда, который держит текст:
`{code: "text_truncated", episode_id, slot, limit}` — ничего не обрезается
молча. Число колонок сетки: 2 (2×2), если ячеек на слайде ≤ 4, иначе 3.
Номера шагов сквозные по документу в порядке Storyboard.

Разбивка списка ингредиентов: строки текста, затем группы через запятую;
пустые элементы отбрасываются. Подписи слайдов («Ингредиенты», «Шаги»,
«Подача», «(продолжение)») берутся из таблицы RU/EN по `--lang` (по умолчанию
— `project.output_lang`, иначе `ru`); язык текста эпизода не переводится —
это волна 3 (№018).

## Эпизоды без текста

Storyboard без текста (волна 2) собирается в слайды без ошибок: в слотах
текста пусто (`caption: ""`, `items: []`, `cells[].text: ""`), предупреждений
нет. Пустая строка и строка из пробелов — тоже «без текста».

## Валидация и проверка

`slides.json` валидируется схемой `schemas/slides.v1.json`
(`razkadr validate --kind slides slides.json`); движок валидирует собственный
выход перед записью (`layout_storyboard`). Тесты (`tests/test_layout.py`)
прогоняют канонические примеры `examples/storyboard.*.json` и синтетические
Storyboard на 0, 1, 7, 30 эпизодов, границы переноса (ровно 12/13 строк,
6/7 шагов), детерминизм и CLI.

## Экспорт (наряд №026)

`razkadr export-html slides.json --out deck.html` — самодостаточная страница
(CSS и JS инлайном, без CDN и внешних запросов) + `deck_assets/` с кадрами
(относительные пути кадров разрешаются относительно каталога slides.json).
Навигация: клавиши (←/→/Home/End/пробел), клик по половинам экрана; печатная
вёрстка `@media print`; тёмная/светлая тема (`prefers-color-scheme` +
переключатель). Каждый таймкод — ссылка на момент источника; источники
берутся из Storyboard (`--storyboard`, по умолчанию `storyboard.json` рядом
со slides.json): YouTube (`watch`/`youtu.be`) получает `t=<секунды>s`,
локальный файл — `file://`+абсолютный путь с `#t=<секунды>` (переносимость не
гарантируется), TikTok и прочие — URL без параметра времени (таймкод остаётся
текстом); без Storyboard таймкоды — текст без ссылок.

`razkadr export-json storyboard.json --out storyboard.out.json` — повторная
валидация по схеме и каноническая перезапись JSON (отдача Storyboard другим
системам). Встроенного плеера нет: видео не копируется (non-goal наряда).
