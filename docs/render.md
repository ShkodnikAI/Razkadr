# Рендер PPTX (наряд №022)

`razkadr render` превращает `slides.json` (выход движка раскладки №021) в
`deck.pptx` на эталонном шаблоне. PPTX — мастер-формат (ADR-0003): PDF
(№024) и Google Slides (№025) получаются из этого файла. Рендер знает
про слоты и кадры, но не про Storyboard; Storyboard используется только
для заметок докладчика (таймкоды начала/конца и источник).

```bash
razkadr render slides.json --out deck.pptx [--template templates/razkadr-default.pptx] \
    [--storyboard storyboard.json] [--min-font-pt 12]
```

Коды выхода: 0 — ок, 1 — slides.json не валиден (проверка по
`schemas/slides.v1.json` перед рендером), 2 — файл/ошибка (шаблон не
найден). Storyboard подставляется автоматически, если `storyboard.json`
лежит рядом со slides.json; без него заметки деградируют до id эпизода и
таймкода слота (предупреждение печатается, если файл не читается).

## Эталонный шаблон

`templates/razkadr-default.pptx` собирается скриптом
`scripts/templates/build_default.py` и лежит в репозитории. Сборка
детерминирована: тест пересобирает шаблон и сравнивает содержимое частей
с закоммиченным файлом байт-в-байт (метки времени zip-записей не
сравниваются).

```bash
python scripts/templates/build_default.py [--out templates/razkadr-default.pptx]
```

В шаблоне ровно пять макетов — по одному на макет раскладки: `title`,
`hero_caption`, `ingredients_list`, `steps_grid`, `serving`. У каждого
именованные плейсхолдеры под слоты slides.json: `heading`, `subheading`,
`frame`, `caption`, `timecode`, `items`, а у `steps_grid` — шесть групп
`cell1..cell6_{number,frame,text,timecode}` (номинальная сетка 3×2;
рендер пересчитывает геометрию под `columns`: 2 → сетка 2×2, 3 → 3×2).

Палитра проекта: бордовый `#6B0F1A`, шампань `#D4AF7F`, кремовый
`#F8F4E9`, графит `#2B2B2B`. Шрифт — DejaVu Sans: есть в LibreOffice и
десктопном Linux по умолчанию, полностью покрывает кириллицу и латиницу.
Рамки, бренд-подпись и фон запечены в макеты (статические фигуры, не
плейсхолдеры) и не попадают на слайды.

## Что делает рендер

- **Плейсхолдеры.** Для каждого слайда slides.json создаётся слайд на
  макете с тем же именем; клоны плейсхолдеров получают геометрию (xfrm),
  `bodyPr` и `lstStyle` из макета явно — рендер не зависит от тонкостей
  наследования в PowerPoint/LibreOffice.
- **Кадры.** Пустой picture-плейсхолдер заменяется картинкой, вписанной
  в бокс плейсхолдера с сохранением пропорций (contain-fit, по центру,
  без кадрирования и растяжения). Кадр ищется относительно каталога
  slides.json; отсутствующий кадр — предупреждение `frame not found`,
  слайд рендерится без него. В `descr` картинки пишется
  `{episode_id} t={t}` — доступность и поиск момента.
- **Автоподгон текста.** Стартовый размер берётся из `lstStyle`
  плейсхолдера шаблона. Текст переносится по словам и ужимается с шагом
  1 pt, пока не влезает в слот; ниже `--min-font-pt` (по умолчанию 12)
  размер не опускается — вместо этого печатается предупреждение
  `text_overflow` (слайд, слот, пол). Маркеры буллитов у `items` —
  литеральные `«• »` префиксы, чтобы метрики замера совпадали с рендером
  один в один.
- **Метод оценки границ.** Ширина строки измеряется Pillow против
  метрик DejaVu Sans (1 pt = 1 px при 72 dpi); перенос — жадный по
  словам, длинные слова режутся посимвольно; высота строки — 1.25 ×
  размер (запас: реальная у DejaVu ≈1.17, PowerPoint single ≈1.2);
  учитываются внутренние отступы `bodyPr` (0.06" по бокам, 0.03"
  сверху/снизу). Тест открывает готовый deck.pptx и повторяет этот
  расчёт независимо для каждого текста — ни один текст не выходит за
  границы слота.
- **Заметки докладчика.** По строке на каждый `source_ref`:
  `{episode_id} {t_start}-{t_end} {источник}` — таймкоды `мм:сс` (или
  `ч:мм:сс`), источник — URL или путь из Storyboard. По слайду можно
  найти момент видео. Без Storyboard: id эпизода и таймкод слота.

## Предупреждения

Все предупреждения печатаются в stderr и входят в итоговую строку
(`N warnings`): `frame not found` (кадр не найден), `text_overflow`
(текст остался на нижней границе шрифта), `cells_overflow` (ячеек
больше, чем вмещает сетка), `placeholder missing` (в шаблоне нет
плейсхолдера с именем слота — пользовательский шаблон №023 неполон).

## Тесты

`tests/test_render_pptx.py` — hermetic (без сети и LibreOffice):
структура шаблона, воспроизводимость сборки, соответствие счётчиков
slides.json, границы текста, автоподгон до пола, заметки, деградации,
CLI. `tests/test_render_pdf.py` (метка `libreoffice`) — конвертация в
PDF через `soffice --headless --convert-to pdf` и читаемость кириллицы и
латиницы в текстовом слое PDF через `pdftotext`; пропускается, если
`soffice`/`pdftotext` нет. Ручная визуальная приёмка в PowerPoint — за
владельцем на шлюзе E.
