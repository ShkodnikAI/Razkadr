# Шлюз B — приёмка волны 1 (Индексатор)

**Нарядов в волне:** #4, #5, #6, #7, #8, #9, #10, #11, #37, #38, #39, #40, #41  
**Протокол:** `docs/acceptance/wave-1.md` (по `docs/acceptance/TEMPLATE.md`)  
**Решает:** аудитор готовит протокол, владелец принимает решение go / go с замечаниями / no-go.

## Критерии
- [ ] `razkadr index` проходит на 8/8 видео эталонного набора без ручных правок (минимум 3 по ссылке)
- [ ] Полнота кандидатов кадров ≥ 95 % эталонных кадров в пределах ±2 с
- [ ] Выборка 50 кадров: брак (дубли, смаз) не более 10 %
- [ ] Язык определён верно на 8/8; WER измерена на 2-минутных фрагментах
- [ ] OCR: ≥ 80 % слов списка ингредиентов на 2 видео с подписями
- [ ] Время и стоимость API на минуту видео по стадиям измерены; порог стоимости задаёт владелец
- [ ] Повторный запуск без платных вызовов и ≥ 5× быстрее
- [ ] Смена провайдера правкой конфига; ключи отсутствуют в логах и артефактах
- [ ] ADR-0006 принят владельцем; ADR-0007 рассмотрен

## No-go
Полнота кандидатов < 95 %; тогда доработка нарядов №6/№9 в той же волне. Блокируется отсутствием наряда №40 (эталонный набор).

## Порядок
1. Все наряды волны закрыты, PR прошли аудит.
2. Аудитор запускает проверки сам (не со слов агента) и заполняет протокол числами из запусков.
3. Демонстрация владельцу, решение записывается в протокол.
4. При go: аудитор уточняет черновики нарядов следующей волны (снимает `draft`).
