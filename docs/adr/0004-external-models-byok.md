# ADR-0004 — Только внешние модели; режим BYOK

**Статус:** accepted (состав провайдеров определяется нарядом 004)
**Дата:** 2026-10-15

## Контекст
Владелец проекта решил не использовать локальные модели. Пользователи могут захотеть применять собственные оплаченные модели для экономии.

## Решение
1. Все ML-функции (ASR, эмбеддинги, VLM/OCR, LLM) выполняются внешними API через слой провайдеров (наряд 033). На серверах и в CLI только CPU-работа: ffmpeg, детекция сцен, хэши, рендер.
2. Поддерживаются режимы ключей: платформенные, BYOK (ключи пользователя), смешанный.
3. BYOK означает API-ключи с оплатой по использованию. Подписки на чат-сервисы, как правило, API-доступа не включают.
4. Ключи не логируются и не попадают в артефакты; при хранении (веб-волны) шифруются.
5. Провайдеры и модели определяются по замерам и проверке условий (наряд 004); смена провайдера не требует правки стадий.

## Последствия
- Себестоимость определяется ценами API: стоимость 1 минуты видео измеряется на шлюзе B.
- Кадры и аудио передаются третьим сторонам: нужны согласие пользователя и политика приватности.
- Зависимость от цен, лимитов и условий провайдеров; смягчается сменяемостью и кэшем.
- При BYOK платформа получает плату только за собственные сервисы; тарифы пересчитываются после замеров.
