# Наряд №008 — Чанки текста: тематическая разбивка с таймкодами

**Волна:** 1 (Индексатор)  
**Стадия:** indexer  
**Размер:** S  
**Исполнитель:** agent  
**Зависит от:** #33, #7  
**Связанные ADR:** —  
**Статус:** open

## Контекст
Для поиска и подписей транскрипт нужен в виде тематических фрагментов. Граница определяется LLM; без LLM работает детерминированная запасная разбивка.

## Контракт
```
transcript.json
→ chunks.json: [{id, t_start, t_end, text, lang}]  — чанки покрывают транскрипт без пропусков и перекрытий
```

## Scope
- Разбивка через LLM (промпт с версией в `prompts/chunking.v1.md`) по границам сегментов ASR; ограничения на длину чанка в параметрах.
- Запасной алгоритм без LLM: по паузам и длине.
- Привязка каждого чанка к исходным сегментам (список id).

## Non-goals
- Реальный LLM-адаптер (№39).
- Суммаризация чанков (волна 3).

## Acceptance criteria
- [ ] Тест на fake-LLM и на запасной алгоритм: покрытие без пропусков и перекрытий
- [ ] Чанки не режут сегмент ASR посередине
- [ ] `chunks.json` валиден по схеме из №35
- [ ] Промпт лежит в репозитории с версией
- [ ] CI зелёный

## Assumptions / Open questions
- Температура 0 и фиксированный формат ответа (JSON); при невалидном ответе LLM используется запасной алгоритм с записью причины в лог.

## Проверка аудитора
- Проверить обработку невалидного ответа LLM.
- Проверить, что нет потери текста при разбивке (конкатенация чанков равна транскрипту).
