# Наряд №010 — Эмбеддинги через API и хранилище векторов за интерфейсом VectorStore

**Волна:** 1 (Индексатор)  
**Стадия:** indexer  
**Размер:** L  
**Исполнитель:** agent  
**Зависит от:** #33, #6, #8, #9  
**Связанные ADR:** ADR-0002  
**Статус:** open

## Контекст
Поиск по теме требует эмбеддингов кадров и текста. Эмбеддинги считаются через провайдера, а векторы хранятся за интерфейсом `VectorStore`. Для ядра (CLI) хранилище локальное и без внешних сервисов.

## Контракт
```
frames.json, chunks.json, ocr.json
→ index/ (векторы + метаданные) и index/manifest.json {провайдер, модель, версия, размерность, число векторов}
VectorStore.search(vector, k, filters) → [(id, score, metadata)]
```

## Scope
- Интерфейсы `Embedder` (через слой провайдеров) и `VectorStore`.
- Реализация хранилища для ядра: SQLite + numpy (точный поиск по косинусной близости); pgvector откладывается до веб-волны (оформить как ADR-0007, статус proposed).
- Эмбеддинги вычисляются после отбраковки кадров (только не отброшенные), пакетами, с кэшем; тексты: чанки и OCR.
- Манифест индекса; при смене провайдера или модели индекс помечается устаревшим и пересобирается.
- Фильтры поиска: источник, интервал времени, минимальная резкость.

## Non-goals
- Гибридный поиск и RRF (№12).
- Реальный адаптер эмбеддингов (№38).

## Acceptance criteria
- [ ] На fake-эмбеддере поиск возвращает ожидаемые результаты (тест)
- [ ] Перезагрузка индекса с диска даёт тот же результат
- [ ] Смена модели помечает индекс устаревшим (тест)
- [ ] Отброшенные кадры не отправляются на эмбеддинг (проверка по счётчику вызовов)
- [ ] Манифест валиден по схеме из №35; ADR-0007 оформлен как proposed
- [ ] CI зелёный

## Assumptions / Open questions

- Проверить корректность размерности при смене модели.
