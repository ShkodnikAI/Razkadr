## Контекст
Все стадии работают одинаково: получают контекст запуска, пишут артефакты, учитывают время и стоимость, кэшируются. Эту общую часть нужно сделать один раз.

## Контракт
```
`razkadr <index|select|text|build|validate|eval|eval-check>`   # подкоманды-заглушки с единым интерфейсом
RunContext: создаёт runs/<run_id>/, контекст-менеджер stage("name") измеряет время, пишет run.json
Кэш стадии: ключ = хэш(входы + параметры + версии); повторный запуск → cache_hit=true, стадия не выполняется
→ запуск тестовой стадии дважды: второй раз cache_hit, run.json валиден по схеме из №35
```

## Scope
- `razkadr.runctx`: RunContext, запись `run.json`, стадии со временем и статусом, ключи кэша, флаг `--force`.
- Конфигурация: поиск `razkadr.toml` (рабочий каталог, затем `~/.config/razkadr/`), переопределение через `--config` и переменные окружения; хэш конфигурации в `run.json`.
- Логирование: структурированное, маскирование секретов (ключи API, токены).
- Каркас подкоманд CLI: общий разбор аргументов, коды выхода, `--version`, `--verbose`.

## Non-goals
- Логика конкретных стадий.
- Слой провайдеров (наряд №33).

## Acceptance criteria
- [ ] Пример из контракта проходит (тест с тестовой стадией)
- [ ] Маскирование секретов проверено тестом (ключ не появляется в логах и в `run.json`)
- [ ] Сбой стадии записывается в `run.json` со статусом и причиной; повторный запуск продолжает с упавшей стадии
- [ ] CI зелёный

## Assumptions / Open questions
- Кэш стадий хранится внутри каталога запуска; общий кэш вызовов провайдеров делается в №33.
