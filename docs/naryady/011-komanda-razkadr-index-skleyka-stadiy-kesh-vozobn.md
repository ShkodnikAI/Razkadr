## Контекст
Пользователь запускает одну команду и получает полный индекс видео. Стадии выполняются по очереди, результаты кэшируются, сбой не заставляет начинать сначала.

## Контракт
```
`razkadr index <файл|URL> [--config razkadr.toml] [--force]`
→ runs/<id>/ со всеми артефактами (ingest, кадры, транскрипт, чанки, OCR, индекс), run.json
→ итог в консоли: число кадров, длина транскрипта, число OCR-кадров, стоимость API, время по стадиям
```

## Scope
- Оркестрация стадий №5–10 через RunContext; возобновление с упавшей стадии.
- Итоговая сводка (в консоли и в `run.json`).
- Сквозной тест на фикстурах и fake-провайдерах.

## Non-goals
- Выбор и сборка Storyboard (волна 2).
- Реальные провайдеры (адаптеры №37–39).

## Acceptance criteria
- [ ] Сквозной тест на фикстуре с fake-провайдерами создаёт все артефакты, и все они валидны по схемам
- [ ] Повторный запуск: все стадии cache_hit, 0 вызовов провайдеров
- [ ] Инъекция сбоя на стадии транскрипта: повторный запуск продолжает с неё, предыдущие стадии не пересчитываются
- [ ] `run.json` содержит время и стоимость по стадиям
- [ ] CI зелёный

## Assumptions / Open questions
- Параллельное выполнение независимых стадий (кадры и транскрипт) допускается, но не обязательно.
