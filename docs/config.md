# Конфигурация Razkadr (razkadr.toml)

Документ описывает конфигурацию уровня волны 0: поиск файла, переопределение
через окружение, обработку секретов и разделы слоя провайдеров (наряд №033,
ADR-0004). Ключи никогда не попадают в логи, `run.json` и текст исключений —
это проверено тестами (`tests/test_providers.py`).

## Где лежит файл

Порядок поиска (первый найденный используется, `src/razkadr/config.py`):

1. Явный путь: `razkadr validate --config путь/до/razkadr.toml` (и аргумент `explicit` в API).
2. `./razkadr.toml` — текущий каталог.
3. `~/.config/razkadr/razkadr.toml` — пользовательский.
4. Ничего не найдено — значения по умолчанию (`{"runs_dir": "runs"}`).

## Переопределение через окружение

Любой ключ переопределяется переменной `RAZKADR_<ИМЯ>` (имя ключа
нижним регистром): `RAZKADR_RUNS_DIR=runs2` задаёт `runs_dir`.

Переменные, похожие на секрет (содержат `key`, `token`, `secret`,
`password`), в конфигурацию не попадают вовсе: их значения уходят в реестр
секретов и используются только для маскирования.

## Секреты: два способа передать ключ

| Способ | Как | Когда использовать |
|---|---|---|
| Через переменную окружения | `api_key_env = "ASR_API_KEY"` — в конфиге имя переменной, само значение берётся из окружения | Рекомендуемый способ |
| Прямо в конфиге | `api_key = "..."` — значение удаляется из эффективной конфигурации и хранится в реестре секретов | Режим BYOK (`[keys] mode = "user"`), когда пользователь сам правит свой локальный toml |

Прямые ключи работают на любом уровне вложенности: ключ с секретным именем
удаляется из конфигурации (и из её хэша) ещё при загрузке и сохраняется в
реестре под точечным именем раздела, например `asr.api_key`. Слой
провайдеров достаёт его оттуда при сборке сервиса. Ключ-суффикс `_env`
(`api_key_env`) секретом не считается — это имя переменной, а не секрет.

Маскирование применяется до сериализации (`deep_mask`): значения
прогоняются через реестр секретов в `run.json`, записях кэша и логах,
затем строка целиком маскируется ещё раз — это ловит и «необычные» ключи
с кавычками, regex-метасимволами и не-ASCII символами.

Если ключ объявлен через `api_key_env`, но переменная не задана или пуста,
слой провайдеров падает с понятной ошибкой вида
`export ASR_API_KEY=<your key> (keys are never logged)` — это ошибка
конфигурации, а не сети.

## Разделы провайдеров

Все ML-функции идут через внешние API (ADR-0004); стадия зависит только от
интерфейса, реализация выбирается конфигурацией (наряд №033). Четыре задачи:

| Раздел | Задача | Метод | Стадия по умолчанию |
|---|---|---|---|
| `[asr]` | речь → текст | `transcribe(audio_path, lang)` | `transcript` |
| `[embeddings]` | векторы текста и кадров | `embed_texts`, `embed_images` | `index` |
| `[vlm]` | описание изображения | `describe_image(path, prompt)` | `ocr` |
| `[llm]` | chat completion | `complete(messages)` | `chunks` |

```toml
[asr]
provider = "fake"            # имя реализации, см. FACTORIES в providers/layer.py
model = "fake-nova-2"        # модель; входит в ключ кэша
api_key_env = "ASR_API_KEY"  # или api_key = "..." (не рекомендуется, маскируется)
max_attempts = 3             # повторы при временных ошибках (TransientError)
base_delay_s = 1.0           # задержка: base_delay * 2^(попытка-1)
requests_per_minute = 60     # троттлинг частоты вызовов
max_concurrency = 1          # параллельные вызовы одного провайдера
model_version = "2"          # версия модели; входит в ключ кэша

  [asr.tariff]
  units = "seconds"          # тарифицируемая единица: seconds | tokens | images
  price = 0.0059             # цена за единицу
  currency = "USD"           # валюта учёта — USD (наряд №033)
  tariff_date = "2026-10-01" # дата тарифа; вносится вручную после наряда №4
```

`[embeddings]`, `[vlm]`, `[llm]` настраиваются так же. В волне 0 доступны
только `fake`-реализации (детерминированные, без сети); реальные адаптеры —
наряды №37–39. Смена провайдера — правка `provider` в toml, код стадий
не меняется (покрыто тестом `test_provider_switch_by_config`).

### Учёт стоимости

Каждый вызов дописывает запись в `provider_calls` файла `run.json`:
стадия, задача, провайдер, модель, единицы (`seconds`/`tokens`/`images`),
стоимость (`amount`, `currency`, `tariff_date`) и признак `cache_hit`.
Стоимость = сумма единиц тарифицируемого вида × цена, округление до 6
знаков. Без раздела `[<задача>.tariff]` вызов записывается с нулевой
стоимостью и датой-маркером `1970-01-01` — пропуск тарифа виден, а не
молча занижен. Тарифы вносятся владельцем вручную (наряд №4 соберёт реальные).

## Ключи и режимы BYOK

```toml
[keys]
mode = "platform"   # платформенные ключи (по умолчанию) | "user" (BYOK)
```

Режим валидируется при сборке слоя: допустимы `platform` и `user`
(ADR-0004 — модели только внешние, с поддержкой BYOK). В режиме `user`
пользователь передаёт свои ключи (обычно через `api_key_env` или прямой
`api_key` в своём локальном toml); платформа ключей не хранит — хранение
в БД и шифрование вынесены в веб-волны (non-goals наряда №033).

## Кэш вызовов

```toml
[cache]
dir = "~/.cache/razkadr/calls"  # по умолчанию; каталог JSON-записей кэша
```

Ключ кэша — sha256 канонического JSON от задачи, имени провайдера, модели,
`model_version` и всех входов/параметров. Повторный вызов с теми же входами
не обращается к провайдеру (счётчик вызовов проверяется тестом), в
`run.json` попадает `cache_hit=true`, стоимость — 0. Записи кэша
маскируются так же, как артефакты.

## Полный пример

```toml
# razkadr.toml
runs_dir = "runs"

[keys]
mode = "user"

[cache]
dir = "~/.cache/razkadr/calls"

[asr]
provider = "fake"
model = "fake-nova-2"
api_key_env = "ASR_API_KEY"
max_attempts = 3
base_delay_s = 1.0
requests_per_minute = 60
max_concurrency = 1

  [asr.tariff]
  units = "seconds"
  price = 0.0059
  currency = "USD"
  tariff_date = "2026-10-01"

[embeddings]
provider = "fake"
model = "fake-embed-v2"

  [embeddings.tariff]
  units = "images"
  price = 0.0001
  currency = "USD"
  tariff_date = "2026-10-01"

[vlm]
provider = "fake"
model = "fake-vision-1"

[llm]
provider = "fake"
model = "fake-gpt-4o-mini"
```

Валидность `run.json` с записями вызовов проверяется схемой
`schemas/run.v1.json`; структура каталога запуска описана в
[artifacts.md](artifacts.md).
