## Контекст
Каждая стадия пишет артефакты в каталог запуска `runs/<run_id>/` и читает артефакты предыдущих. Форматы нужно зафиксировать заранее, чтобы стадии разрабатывались независимо.

## Контракт
```
runs/<run_id>/
  run.json          # запуск: версии, конфиг-хэш, стадии (время, статус), вызовы провайдеров (токены/секунды, стоимость, cache_hit)
  source.json       # источник: путь/URL, sha256, длительность, fps, разрешение, дорожки
  normalized.mp4, audio.wav
  frames/*.jpg, frames.json    # t, scene_id, sharpness, phash, exposure
  transcript.json   # сегменты (t_start, t_end, text, lang, speaker?) + язык
  chunks.json       # тематические чанки с таймкодами
  ocr.json          # текст на кадрах: frame, t, text, lang
  index/manifest.json   # провайдер, модель, версия, размерность, число векторов
  storyboard.json   # см. №2
→ `razkadr validate --kind <source|frames|transcript|chunks|ocr|index|run> <файл>` проверяет каждый артефакт по схеме
```

## Scope
- Схемы `schemas/<kind>.v1.json` для каждого артефакта, у каждой `schema_version`.
- Валидаторы и расширение команды `validate` (`--kind`).
- Примеры валидных артефактов в `examples/artifacts/` (небольшие).
- `docs/artifacts.md`: структура каталога запуска, какая стадия что пишет и читает, правила совместимости.

## Non-goals
- Реализация стадий.
- Изменение схемы Storyboard (наряд №2).
