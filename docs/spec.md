# Техническое задание: сервис «видео → эпизоды → текст → презентация»

**Рабочее название:** Raskadr (раскадр)
**Версия:** v0.4
**Дата:** 2026-10-15
**Статус:** черновик. Изменения относительно v0.3: новый конвейер со Storyboard в центре, шаблоны, мультиязычность, первый пресет «рецепты», вывод в PPTX/PDF/Google Slides сразу.

---

## 1. Суть

Пользователь загружает видео и задаёт тему или сценарий. Сервис один раз индексирует видео, находит качественные кадры и эпизоды по описанию, готовит к каждому короткий текст (по транскрипту или по описанию кадра) и собирает презентацию с таймкодами-привязкой к оригиналу.

Продукт: **документ с доказательной привязкой к видео** (кадр + текст + таймкод), а не просто подборка кадров.

Коллаж, статья и конспект из v0.3 теперь являются **макетами и пресетами**, а не отдельными генераторами.

## 2. Области применения

Рецепты (первый тестовый пресет), UX-исследования и интервью, встречи и вебинары, инспекции и обход объектов, недвижимость и ремонт, видеопродакшн (селекты, питчи), продажи и маркетинг, статьи по интервью, спорт-разбор, личный архив.

Приоритет проверки: рецепты (тест). Рыночный приоритет определяется после Этапа 0 (кандидаты: UX-исследования, встречи/вебинары, инспекции).

## 3. Конвейер и модульность

```
Источник → Индексатор → Отбор → Текст → Раскладка → Рендер/Экспорт
                           ↘        ↓        ↙
                         STORYBOARD (JSON) — точка правки человеком
```

Каждая стадия принимает и возвращает типизированный JSON (JSON Schema, версионируется). Реализацию стадии можно заменить, не трогая остальные. Один наряд = один контракт стадии.

### 3.1. Storyboard (центральный объект)

```json
{
  "schema_version": "1.0",
  "project": {"id": "...", "title": "...", "preset": "recipe", "output_lang": "ru"},
  "sources": [{"id": "v1", "path": "...", "duration_s": 840, "detected_lang": "en"}],
  "episodes": [
    {
      "id": "e1",
      "role": "ingredients",          // роль в структуре документа (из пресета)
      "source_id": "v1",
      "t_start": 12.4, "t_end": 31.0,
      "frame": {"path": "frames/v1_000412.jpg", "t": 18.2, "score": 0.87,
                "score_parts": {"sharpness": 0.9, "aesthetic": 0.8, "relevance": 0.91}},
      "alternatives": [{"path": "...", "t": 20.1, "score": 0.81}],
      "text": {
        "mode": "condensed",          // verbatim | condensed | described
        "source_lang": "en",
        "original": "...",
        "output": "...",
        "output_lang": "ru"
      },
      "user_edited": false
    }
  ]
}
```

Правила: пользовательские правки (замена кадра, текста, порядка) сохраняются в Storyboard и не перезаписываются при повторной генерации (`user_edited`).

### 3.2. Стадии

| Стадия | Вход → выход | MVP-реализация |
|---|---|---|
| Источник | файлы/ссылки → нормализованное видео | загрузка файлов, ffmpeg |
| Индексатор | видео → кадры, транскрипт, чанки, эмбеддинги, OCR экранного текста | PySceneDetect, faster-whisper/WhisperX, мультиязычная эмбеддинг-модель, wtpsplit, pgvector |
| Отбор | тема/пресет → кандидаты эпизодов | гибридный поиск (кадры + текст + ключевые слова, RRF) + скоринг по профилю пресета |
| Текст | эпизоды → текст каждого | LLM: дословно / сжато / описание кадра; перевод на язык вывода |
| Раскладка | Storyboard + макет → слайды | правила макетов, слоты |
| Рендер/экспорт | слайды + шаблон → файлы | PPTX (мастер), PDF, Google Slides, HTML, JSON |

## 4. Шаблоны (три независимых уровня)

1. **Сценарные пресеты** (домен): структура документа (роли эпизодов), профиль скоринга кадров, промпты текста, словарь терминов.
2. **Макеты** (layout): герой + подпись, сетка 2×2, лента шагов, коллаж, до/после, цитата с кадром.
3. **Брендинг/шаблон оформления**: цвета, шрифты, логотип, мастер-слайды.

**Собственный .pptx пользователя** используется как шаблон через python-pptx: слоты (заголовок, изображение, подпись, таймкод, заметки) сопоставляются с плейсхолдерами. Содержание отделено от оформления; один Storyboard выводится в любой формат.

## 5. Мультиязычность (три слоя)

- **Язык видео:** автоопределение, транскрипт хранится в оригинале, допускается смешанная речь.
- **Язык запроса:** мультиязычные эмбеддинги; запасной вариант — перевод запроса на язык индекса.
- **Язык документа:** задаётся отдельно; LLM пересказывает и переводит. Видео EN → презентация RU — штатный сценарий.
- Рендер: шрифты для кириллицы и CJK; RTL (арабский/иврит) — после MVP.
- MVP: языки вывода RU и EN.

## 6. Первый пресет: «Рецепт»

**Тест:** 5–10 видео рецептов (разные стили: с голосом, без голоса, с экранными подписями, на RU и EN).

**Структура документа (роли эпизодов):**
1. Титул: готовое блюдо (лучший «hero»-кадр финального блюда).
2. Ингредиенты: кадр выкладки продуктов и/или экранный список (OCR); состав текстом с количествами.
3. Подготовка: нарезка, замес и т. п.
4. Шаги приготовления: по одному эпизоду на ключевое действие (кадр + 1–2 предложения + таймкод).
5. Подача и советы.

**Профиль скоринга кадров:** резкость; еда/руки в кадре крупным планом; отсутствие пара/блика/пересвета (штраф); для hero-кадра эстетика и «готовое блюдо»; для ингредиентов читаемость экранного текста; дедупликация похожих шагов.

**Особенности:** многие рецепты без речи (текст только с экрана или нужен VLM-описатель); количества и единицы измерения нужно нормализовать при переводе (cup → г/мл по настройке); температуры и время сохранять точно.

**Критерии успеха Этапа 0:** на размеченном наборе (для каждого видео вручную отмечены кадры «готовое блюдо», «ингредиенты» и 5–8 ключевых шагов) попадание в топ-3 кандидатов ≥ 80 % для hero и ключевых шагов; сравнение двух моделей эмбеддингов и вариантов поиска на этом же наборе.

## 7. Форматы вывода (все в MVP)

- **PPTX** — мастер-формат, строится из Storyboard + шаблона через python-pptx.
- **PDF** — конвертация из PPTX (LibreOffice headless); альтернативно HTML → PDF.
- **Google Slides** — загрузка PPTX в Google Drive с конвертацией в Slides (Drive API, OAuth пользователя). Это дешевле, чем строить презентацию через Slides API; расхождения в шрифтах/макетах проверять тестами.
- **HTML** (интерактивный, с кликабельными таймкодами), **JSON** (Storyboard) — для просмотра, правок и интеграций.
- Позже: MP4-фрагменты, DOCX, SRT, формат импорта Металогоса.

Риск: все три формата сразу увеличивают объём тестирования рендера. Митигация: единый визуальный тест (скриншот каждого слайда, сравнение), один эталонный шаблон на старте.

## 8. Архитектура

```
[Веб-интерфейс: загрузка, редактор Storyboard, превью слайдов]
        │
[API + оркестратор: Python (FastAPI)]   ← Металогос рассматривать после Этапа 2 (решение через ADR)
        │
[Очередь: Celery/RQ + Redis]
        │
[Воркеры: ffmpeg, PySceneDetect, ASR, эмбеддинги, OCR, LLM, рендер]
        │
[PostgreSQL+pgvector | S3-хранилище кадров и видео]
```

Решение: до Этапа 2 весь бэкенд на Python (ADR-001). Металогос не является зависимостью MVP.

## 9. Технологический стек (кандидаты)

| Слой | Технологии |
|---|---|
| Видео/кадры | ffmpeg, PySceneDetect |
| ASR | faster-whisper / WhisperX |
| Сегментация текста | wtpsplit |
| Эмбеддинги | **SigLIP 2 (Apache 2.0) как безопасный базовый вариант**; jina-clip-v2 — сравнить, но проверить лицензию на коммерческое использование (CC BY-NC) |
| OCR экранного текста | PaddleOCR / Tesseract (мультиязычный) |
| Описание кадров | VLM (Qwen2.5-VL или аналог) — для немых рецептов нужен уже в MVP-пилоте |
| Поиск | pgvector (или Qdrant) + RRF |
| LLM | локальная модель или API (решение по приватности) |
| Презентации | python-pptx, LibreOffice (PDF), Google Drive API |
| Загрузка | Uppy + tus; ссылки (yt-dlp) — только локальный/пилотный режим, юридически рискованно для хостед-сервиса |
| Фронт | React/Vue |

## 10. Монетизация (черновик, пересмотреть после расчёта себестоимости)

Кредитная модель: 1 кредит ≈ 1 минута исходного видео (индексация); генерация и экспорт — отдельная тарификация. Тарифы Free / Starter / Pro / Team и годовая скидка — как в v0.3, цены не фиксировать до измерения реальной стоимости минуты на Этапе 0. Доп. источники: платные шаблоны и пресеты, white-label, интеграции.

## 11. Риски

1. Три формата вывода + мультиязычность + шаблоны → разрастание. Меры: контракты полные, реализаций минимум (1 пресет, 1–2 макета, 2 языка).
2. Качество отбора: проверяется на размеченном наборе (§6), без него сравнения «на глаз».
3. Лицензии моделей (jina-clip-v2, VLM, LLM) для коммерческого использования.
4. Авторские права на загружаемые видео и ToS платформ (yt-dlp).
5. Немые видео и экранные подписи: нужны OCR и VLM.
6. Расхождения PPTX → Google Slides / PDF (шрифты, автоподгон текста).
7. Себестоимость: хранение/трафик видео и LLM, а не только ASR.
8. Приватность: локальный LLM vs внешние API.

## 12. Дорожная карта

- **Этап 0 — CLI-прототип + набор для оценки.** Видео рецепта + пресет `recipe` → `storyboard.json` + `deck.pptx` + `deck.pdf`. Размеченный набор, метрики, сравнение моделей. Замер себестоимости минуты.
- **Этап 1 — полный конвейер.** Транскрипт, перевод RU↔EN, правка Storyboard (JSON), PPTX по своему шаблону, загрузка в Google Slides.
- **Этап 2 — веб-оболочка.** Очередь, редактор Storyboard, превью слайдов, аккаунты, кредиты.
- **Этап 3 — новые пресеты** (второй домен: вебинары/UX/инспекции), до/после, MP4-фрагменты, диаризация.
- **Этап 4 — экспорт и интеграции:** DOCX, Notion/Obsidian, Металогос, публичные ссылки.
- **Этап 5 — команды, API, white-label.**

## 13. Процесс работы (наряды и ADR)

Без изменений относительно §8 v0.3: наряд = атомарная задача с контрактом (вход → ожидаемый выход, scope, non-goals, acceptance criteria), цикл sync → факты → реализация → PR, ADR в `docs/adr/`. Наряд теперь привязывается к стадии конвейера и версии схемы Storyboard. Не тратить на процесс больше времени, чем на Этап 0.

## 14. Открытые вопросы

1. Где взять 5–10 тестовых видео рецептов и кто размечает эталон?
2. Приватность: локальный LLM vs внешние API; какое железо (GPU) доступно?
3. Personal tool или мультипользовательский режим с первого дня?
4. Нужен ли перевод единиц измерения (cup → граммы) по умолчанию?
5. Google Slides: достаточно ли загрузки PPTX с конвертацией (требует OAuth пользователя)?
6. Финальные цены и лимиты free-тира (после расчёта себестоимости).
