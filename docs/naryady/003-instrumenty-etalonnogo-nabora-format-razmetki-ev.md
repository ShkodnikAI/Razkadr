## Контекст
Метрики качества считаются на размеченном наборе видео. Видео и разметку соберёт владелец позже (наряд №40); здесь делаются формат и проверка целостности, чтобы сбор не задерживал разработку.

## Контракт
```
data/eval/videos/<id>.mp4  +  data/eval/labels/<id>.json  +  data/eval/SOURCES.md
→ `razkadr eval-check data/eval`
→ "N видео, N разметок, нарушений нет" (код 0) либо список нарушений (код 1)
```

Формат `labels/<id>.json`:
```json
{
  "video_id": "ru_voice_01",
  "tags": ["ru", "voice"],
  "hero": [{"t": 612.0}],
  "ingredients": [{"t": 14.5}],
  "steps": [{"t": 40.0, "note": "нарезка лука"}, {"t": 95.0, "note": "обжарка"}]
}
```
Допуск совпадения времени: ±2 с (параметр).

## Scope
- `schemas/eval_labels.v1.json` и валидатор.
- `razkadr eval-check`: у каждого видео есть разметка и запись в SOURCES, таймкоды в пределах длительности (через ffprobe), минимум 1 hero, 1 ingredients, 5 steps, нет дубликатов времени, теги из словаря (`ru|en|voice|silent|onscreen-text|poor-quality`).
- Шаблон `data/eval/SOURCES.md` (поля: id, ссылка, дата скачивания, условия использования, локальный файл, теги) и `data/eval/README.md` с инструкцией для владельца.
- `.gitignore` для видео остаётся; в репозитории только разметка, SOURCES и README.

## Non-goals

- Подсчёт метрик поиска (наряд №15).
