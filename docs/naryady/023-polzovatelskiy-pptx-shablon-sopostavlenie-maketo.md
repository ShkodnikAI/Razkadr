## Контекст
Брендирование под шаблон пользователя: `razkadr render --template my.pptx` заполняет слайды в стиле его шаблона. Пользователь не правит код, а следует соглашению об именах.

## Контракт
```
`razkadr template-check my.pptx`
→ отчёт: для каждого макета (title, hero_caption, ingredients_list, steps_grid, serving) найден ли layout и все ли плейсхолдеры слотов; код 0, если можно рендерить, иначе 1 с понятным списком, чего не хватает

`razkadr render slides.json --template my.pptx --out deck.pptx`
→ слайды в стиле шаблона
```
Соглашение: layout называется `razkadr:<макет>`; плейсхолдеры слотов — по имени shape (`slot:title`, `slot:caption`, `slot:image_1`, `slot:timecode` и т. д.); полный список в `docs/templates.md`.

## Scope
- Загрузчик пользовательского шаблона по соглашению об именах; необязательные слоты (например, таймкод) могут отсутствовать, обязательные — нет.
- `razkadr template-check` и подробная инструкция `docs/templates.md` с картинками-схемами слотов (текстовыми) и примером подготовки шаблона в PowerPoint.
- Тесты на трёх сгенерированных шаблонах: эталонный, с перенумерованными плейсхолдерами, с недостающим layout (понятная ошибка).

## Non-goals
- Автоматический разбор произвольных чужих шаблонов без соглашения.
- Google Slides.

## Acceptance criteria
- [ ] `template-check` на эталонном шаблоне даёт код 0, на шаблоне без layout — код 1 с перечнем недостающего
- [ ] Рендер на втором (отличающемся) шаблоне даёт deck.pptx с заполненными слотами (тест по содержимому)
- [ ] `docs/templates.md` написан и содержит пошаговую инструкцию для пользователя
- [ ] CI зелёный
