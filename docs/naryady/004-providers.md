# Наряд №004 — Выбор провайдеров API: условия, задержка, стоимость

**Статус:** open (блокируется: нужны API-ключи кандидатов)
**Волна:** 0
**Стадия конвейера:** инфраструктура / решения
**Связанные ADR:** 0002, создаёт 0004
**Зависит от:** №001

## Контракт
```
API-ключи кандидатов + 1 минута тестового видео (с речью) + 20 тестовых кадров
→ docs/providers.md: таблица «задача → провайдер/модель → задержка → стоимость за единицу → стоимость за 1 минуту видео → замечания о качестве»
→ docs/adr/0004-external-models-byok.md: условия провайдеров по первоисточникам и решение о составе провайдеров по умолчанию
```

Задачи и кандидаты определяются в начале наряда, цены и условия проверяются по официальным страницам провайдеров на дату замера:
- ASR (русский и английский, таймкоды на уровне слов или сегментов, автоопределение языка);
- эмбеддинги кадров и текста (мультимодальный API) либо описание кадров VLM + текстовые эмбеддинги;
- VLM (описание кадра, OCR экранного текста);
- LLM (сжатие текста, перевод, разбивка на чанки).

## Scope
- Замеры задержки и стоимости, полученные запуском (скрипты в `scripts/providers/`).
- Проверка условий каждого провайдера: коммерческое использование результатов, хранение и обучение на данных пользователя, региональные ограничения, лимиты запросов.
- Рекомендация набора по умолчанию и запасных провайдеров.

## Non-goals
- Реализация слоя провайдеров (наряд 033).
- Окончательный выбор подхода к эмбеддингам (ADR-0002, после волны 2).
- Юридическая консультация: вывод помечается как требующий проверки при коммерческом запуске.

## Acceptance criteria

- [ ] Определён набор по умолчанию и запасной
- [ ] PR содержит `Closes #004`

## Assumptions / Open questions
- У владельца есть или будут API-ключи минимум двух провайдеров для сравнения.
- Бюджет на замеры невелик (минуты видео, десятки кадров).
