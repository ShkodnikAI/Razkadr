# ADR-0007 — VectorStore ядра: SQLite + numpy; pgvector позже

**Статус:** proposed
**Дата:** 2026-10-16

## Контекст
Индексатору (наряд 010) нужно хранилище векторов за интерфейсом `VectorStore`. Объём ядра — порядка 10^5 векторов на запуск (кадры после отбраковки, чанки, OCR-тексты одного видео), поиск — точный по косинусной близости. Веб-волна (6+) потребует многопользовательских индексов и, вероятно, серверной БД.

## Решение
- В CLI-ядре хранилище локальное и без внешних сервисов: метаданные и id в SQLite, матрица векторов в файле `vectors.bin` (float32, N×dim), поиск точный — косинусная близость средствами numpy (нормализация на запросе, скалярное произведение).
- Фильтры поиска (источник, интервал времени, минимальная резкость, пространство кадров/чанков/OCR) применяются в SQL до скоринга numpy.
- pgvector (или другой ANN-хранилище) откладывается до веб-волны: интерфейс `VectorStore` не меняется, ядро не тащит серверную БД в зависимости.
- Детерминизм: равные оценки упорядочиваются по id, поэтому одинаковые данные и запрос дают одинаковый результат.

## Последствия
- Точный поиск O(N) на запрос: при 10^5 векторах и dim ~10^3 это десятки миллисекунд (замер в PR наряда 010); если веб-волна потребует больше — добавляется ANN-реализация за тем же интерфейсом.
- Матрица читается с диска (memory-map): поиск не требует загрузки всего индекса в память процесса заранее.
- SQLite-файл и `vectors.bin` — артефакты запуска, переносятся вместе с run-каталогом.
