# Наряд №012 — Гибридный поиск кадров: векторы кадров + векторы текста + ключевые слова, RRF

**Волна:** 2 (Отбор)  
**Стадия:** select  
**Размер:** M  
**Исполнитель:** agent  
**Зависит от:** #10  
**Связанные ADR:** ADR-0002  
**Статус:** open

## Контекст
Ядро отбора: по текстовому запросу найти лучшие кадры. Сигналы: близость запроса к кадру, к тексту окружающего чанка/OCR и совпадение ключевых слов (BM25). Сигналы объединяются через RRF.

## Контракт
```
runs/<id>/index + запрос "готовое блюдо" (+ язык запроса)
→ список [{frame, t, score, score_parts: {image, text, keyword}, rank_parts}] по убыванию score
```
`score_parts` обязателен: по нему аудитор и eval понимают, какой сигнал сработал.

## Scope
- Три сигнала с независимым включением/выключением в конфигурации (нужно для сравнения в №15).
- BM25 по тексту чанков и OCR (реализация без внешних сервисов).
- RRF с параметром k; веса сигналов в конфигурации.
- Привязка текстовых сигналов к кадрам по времени (кадр наследует чанк/OCR, в окно которых попадает, с параметром окна).
- Перевод запроса на язык видео (слой LLM), если язык запроса отличается; результат перевода пишется в `score_parts`/лог.
- Фильтры: интервал времени, минимальная резкость, исключение отбракованных кадров.

## Non-goals
- Выбор эпизодов по ролям (№14).
- Сравнение подходов на эталоне (№15).

## Acceptance criteria
- [ ] Тесты на fake-эмбеддере: каждый сигнал отдельно и RRF вместе дают ожидаемый порядок на игрушечном индексе
- [ ] Отключение сигнала меняет результат ожидаемым образом (тест)
- [ ] Результат детерминирован
- [ ] `score_parts` присутствует у каждого результата
- [ ] CI зелёный

## Assumptions / Open questions
- Окно привязки текста к кадру по умолчанию ±5 с; подбирается на эталоне (шлюз C).

## Проверка аудитора
- Проверить на ручном примере, что RRF считается по формуле (ранги, а не сырые оценки).
- Проверить поведение при пустом OCR или транскрипте.
