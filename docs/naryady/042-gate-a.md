**Решает:** аудитор готовит протокол, владелец принимает решение go / go с замечаниями / no-go.

## Критерии
- [ ] Схема Storyboard валидирует оба валидных примера и отклоняет невалидный с JSON-путём ошибки
- [ ] Схемы артефактов стадий и каталог запуска задокументированы (`docs/artifacts.md`)
- [ ] Слой провайдеров работает на fake-провайдерах; ключ не попадает в логи и артефакты (тест)
- [ ] Фикстуры генерируются и используются тестами; CI с ffmpeg зелёный
- [ ] `razkadr eval-check` работает на фикстуре; инструкция для владельца по сбору набора написана

## No-go
Схемы не покрывают данные стадий (выяснится при проверке против нарядов №5–11), либо CI нестабилен.

## Порядок
1. Все наряды волны закрыты, PR прошли аудит.
2. Аудитор запускает проверки сам (не со слов агента) и заполняет протокол числами из запусков.
3. Демонстрация владельцу, решение записывается в протокол.
4. При go: аудитор уточняет черновики нарядов следующей волны (снимает `draft`).
