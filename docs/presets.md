# Пресеты: формат (наряд №013)

Пресет — сценарий предметной области в чистых данных: какие **роли** кадров нужны документу, как каждая роль **ищется** (запросы по языкам) и **скорится** (веса сигналов), сколько эпизодов каждой роли допустимо (**квоты**), какие **ограничения** качества применяются и в каком порядке роли идут в документе. Пресеты живут в `presets/*.yaml`; добавление роли или нового пресета не требует правок кода — загрузчик не знает ничего о предметных областях, имена ролей для него непрозрачные строки (проверка аудитора: в коде нет захардкоженных ролей рецепта).

Первый пресет — `presets/recipe.yaml` (кулинарные видео: hero → ingredients → prep → steps → serving). Запросы и веса — стартовые, выбраны при проектировании пресета, уточняются по метрикам шлюза C (наряды №015/№016).

## Загрузка и валидация

```bash
razkadr validate --kind preset presets/recipe.yaml   # ok / список проблем, exit 0/1/2
```

Программно:

```python
from razkadr.presets import load_preset, PresetError

try:
    preset = load_preset("presets/recipe.yaml")
except PresetError as exc:
    print(exc)   # путь к файлу + все проблемы сразу
```

`load_preset` читает YAML, валидирует документ по схеме `schemas/preset.v1.json`, затем проверяет семантику, которую схема выразить не может:

- `order` перечисляет каждую роль ровно один раз (нет пропущенных и посторонних);
- у каждой роли `max >= min` (когда `max` не `null`);
- веса сигналов каждой роли в сумме дают 1 (допуск 1e-6);
- запросы не пустые и не состоят из пробелов.

Все ошибки собираются в один `PresetError` с путём к файлу. После проверок загрузчик заполняет значения по умолчанию (`candidates: 20`, `alternatives: 3`) и возвращает нормализованный словарь; входные данные не изменяются.

## Поля документа

| Поле | Тип | Что означает |
|---|---|---|
| `schema_version` | semver-строка | Версия формата пресета; схема проверяет мажорную версию 1. |
| `name` | `^[a-z][a-z0-9_-]*$` | Стабильный идентификатор для конфига и CLI (`--preset recipe`). |
| `title` | строка | Человекочитаемое имя пресета. |
| `description` | строка | Свободное описание: для чего пресет, откуда числа. |
| `roles` | объект `имя → roleSpec` | Роли документа. Имена ролей свободные (>= 1 роль). |
| `order` | массив имён | Порядок ролей в документе; каждая роль ровно один раз. |
| `min_step_gap_s` | число > 0 | Минимальный интервал в секундах между соседними эпизодами одной роли (шаги не должны собираться на одной сцене). |

## Спецификация роли (`roleSpec`)

| Поле | Тип | Обязательное | Что означает |
|---|---|---|---|
| `min` | целое >= 0 | да | Минимум эпизодов роли в Storyboard. |
| `max` | целое >= 0 или `null` | да | Максимум эпизодов; `null` — без ограничения. |
| `queries` | объект `язык → [строки]` | да | Поисковые запросы по языкам (v1: `ru`, `en`); минимум один язык, минимум один непустой запрос. |
| `weights` | объект `сигнал → число [0,1]` | да | Веса сигналов поиска; сумма = 1. Набор сигналов задаёт стадия отбора (наряд №014). Сейчас доступны: `embedding` (визуальная близость, наряд №010), `sharpness`, `exposure` (стадия кадров, наряд №006). |
| `constraints` | объект | нет | Ограничения кандидатов: `min_sharpness` (кадры ниже — не кандидаты), `face_penalty`, `hands_penalty` (штрафы за срабатывание детекторов лиц/рук). |
| `candidates` | целое >= 1 | нет (20) | Сколько лучших кадров-кандидатов рассматривать для роли. |
| `alternatives` | целое >= 0 | нет (3) | Сколько запасных кадров хранить в Storyboard как `alternatives`. |

## Как добавить роль

Только правка YAML: добавить блок в `roles` и имя в `order`, проверить:

```bash
razkadr validate --kind preset presets/recipe.yaml
```

Пример синтетической роли:

```yaml
roles:
  dessert:
    min: 0
    max: 2
    queries:
      ru: ["десерт"]
      en: ["dessert"]
    weights:
      embedding: 0.7
      sharpness: 0.3
order: [hero, dessert]   # полупорядок — все роли ровно один раз
```

Тест `test_new_role_requires_only_yaml` подтверждает: изобретённая роль загружается, валидируется и получает значения по умолчанию без единой правки кода.

## Как добавить пресет

Создать `presets/<name>.yaml` с теми же полями (`name` — уникальный, из `^[a-z][a-z0-9_-]*$`). Схема `schemas/preset.v1.json` общая; менять принятые схемы в нарядах нельзя — новый формат пресета потребует новой мажорной версии схемы (v2) и явного пункта в наряде.
