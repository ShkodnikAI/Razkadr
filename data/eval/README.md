# Эталонный набор: как добавить видео и разметить его

Эталонный набор — это размеченные видео рецептов, на которых считаются
метрики качества поиска кадров (наряд №15) и проверяются шлюзы. Видео и
разметку добавляет владелец (наряд №40); этот README объясняет формат.
Инструменты уже работают: `razkadr eval-check` проверяет целостность набора,
`razkadr validate --kind eval_labels` проверяет один файл разметки.

## Структура каталога

```
data/eval/
  videos/<id>.mp4    видео (в git не попадает, см. .gitignore)
  labels/<id>.json   разметка видео: отмеченные моменты по ролям
  SOURCES.md         таблица происхождения: одна строка на видео
```

`id` — одно и то же имя во всех трёх местах: файл `videos/ru_voice_01.mp4`,
разметка `labels/ru_voice_01.json`, поле `video_id` внутри разметки и строка
с `ru_voice_01` в SOURCES.md. Допустимые символы id: латиница, цифры,
точка, дефис, подчёркивание.

## Шаг 1. Добавить видео

Скачайте видео и положите его в `data/eval/videos/<id>.mp4` (формат — mp4).
Видео не коммитится: достаточно, что оно лежит в каталоге локально.
Добавьте строку в `data/eval/SOURCES.md` (шаблон и пояснения — в самом
файле), например:

```
| ru_voice_01 | https://example.com/watch?v=abc | 2026-10-16 | CC BY 4.0 | videos/ru_voice_01.mp4 | ru, voice |
```

## Шаг 2. Разметить моменты

Создайте `data/eval/labels/<id>.json` по схеме `eval_labels.v1.json`:

```json
{
  "schema_version": "1.0",
  "video_id": "ru_voice_01",
  "tags": ["ru", "voice"],
  "hero": [{"t": 612.0}],
  "ingredients": [{"t": 14.5}],
  "steps": [
    {"t": 40.0, "note": "нарезка лука"},
    {"t": 95.0, "note": "обжарка"},
    {"t": 150.0, "note": "добавление бульона"},
    {"t": 210.0, "note": "варка"},
    {"t": 300.0, "note": "подача"}
  ]
}
```

Роли моментов (время `t` — секунды от начала видео, опционально `note` —
пояснение для человека):

- `hero` — аппетитный главный кадр готового блюда; минимум 1;
- `ingredients` — раскладка ингредиентов; минимум 1;
- `steps` — шаги процесса по порядку; минимум 5.

Теги — только из словаря: `ru`, `en` (язык), `voice`, `silent` (есть/нет
речь), `onscreen-text`, `poor-quality`. Минимум 1 тег.

Допуск совпадения времени — ±2 с (меняется флагом
`razkadr eval-check --tolerance-s`): при сравнении с отобранными кадрами
метка считается совпавшей, если кадр в пределах допуска. Два момента одной
роли ближе допуска друг к другу считаются дубликатами — eval-check такое
отметит как нарушение.

## Шаг 3. Проверить

```
razkadr eval-check data/eval
razkadr validate --kind eval_labels data/eval/labels/ru_voice_01.json
```

Первая команда проверяет весь набор (файлы, SOURCES, минимумы ролей,
дубликаты, таймкоды внутри длительности видео) и печатает либо
«N видео, N разметок, нарушений нет», либо список нарушений; вторая —
схему одного файла разметки с JSON-путём ошибки.

## Что проверяет eval-check

- у каждого видео есть разметка `labels/<id>.json` и запись в SOURCES.md;
- у каждой разметки есть видео (наполовину размеченное видео — нарушение);
- разметка валидна по схеме: неизвестные теги, отрицательное время,
  неизвестные поля — нарушение с JSON-путём;
- `video_id` совпадает с именем файла;
- минимумы ролей: 1 hero, 1 ingredients, 5 steps;
- нет дубликатов времени в пределах допуска (по умолчанию 2 с);
- все таймкоды не выходят за длительность видео (ffprobe).
